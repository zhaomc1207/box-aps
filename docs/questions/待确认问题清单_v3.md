# 待确认问题清单 v3

说明：以下仅补充 `0403-科大-联宝APS业务交流-逐字稿文本.txt` 中已经能确认的回答；逐字稿仍不能确认的，先保留为空。

1. mcode是什么？
   答：`mcode` 本质上就是 BU，是优先级、UPH、约束等配置的关键业务分类维度。

2. 已经开立的工单，是否必须沿用原来的排程结果，不能重新调整？
   答：按当前规则表口径，已经开立待生产的工单原则上沿用原排程日期，不作为重新排产主对象。

3. 重新排程时，上一版已经排好的结果，是必须保留，还是允许重新分配？

4. 本次排程到底按“需求数量”安排，还是按“计划生产数量”安排？

5. **一个订单是否允许只先排一部分数量，剩余数量留到后面再排？**

6. **一个订单是否允许同时分到多条线生产？**

7. **一个订单是否允许拆到多个班次生产？**

8. 判断一个订单能不能开始排，除了看齐套日期，还要不要同时看齐套状态？
   答：逐字稿口径更看齐套相关日期，状态字段本身不是主要卡控项。

9. 部分齐套的订单，是否允许先做已经齐套的那部分？

10. **如果一个订单的齐套日期已经晚于交期，是否仍然要安排生产？**

11. **一个订单同时有 OTS、FPSD、Ship Date 时，排程先保证哪个日期？**

12. 同一个订单同时命中多条优先规则时，是只按最高一条，还是多条一起生效？

13. 如果产能不够，是先保交付，还是先尽量多排数量？

14. 产品和线体的对应关系，是“只能排到这些线”，还是“优先排到这些线”？
    答：逐字稿和规则表口径是“先满足线体和机型的匹配关系”，在可排线集合内再按线体对应机型的优先顺序排。

15. Cell线是什么？

16. Fast Ship、小单、定制化订单上 Cell 线，是必须这样排，还是优先这样排？
    答：规则表口径是“优先排 Cell 线”，不是逐字稿中明确说死的绝对硬锁。

17. 同一条线在同一个班次里，是否允许同时安排多个机型？
    答：允许。业务规则里专门要求优化“同线体同班次内的机型换线次数最少”，并要求“同线体同班次内相同机型合并排序”，这说明同一线同一班内可能出现多个机型，只是要尽量少切换。

18. 是否允许跨班连续生产？

19. FIX 订单是整单固定，还是只固定指定数量？
    答：当前样例口径下，`FIX` 按整单固定处理；`fix demand input` 的顺序也已在前端尽量准备好。

20. 如果 FIX 订单只固定了一部分，剩余数量是否还允许继续排？

21. 如果 FIX 指定的位置和预留时间冲突，最终以哪个为准？

22. FAI 的首件数量和等待时间，是固定规则，还是不同项目分别设置？
    答：等待时间不是写死 8 小时，而是通过 `lead_time` 配置；业务规则文档中的“2pcs + 8小时”是示例，不应直接写死成统一常数。

23. FAI 首件没有通过之前，后续数量是否绝对不能投产？
    答：是。业务规则文档和逐字稿口径都是“首件验证 pass 后方可投入剩余订单”。

24. `aps_merge_priority_setting_input`在脱敏数据中不存在,是否意味着订单不需要合并；如果不是，那是否是所有订单都先合并再排，还是只有满足条件的订单才先合并？
    答：逐字稿说明这类 merge 规则不是针对已经形成 `lot` 和已经 fixed 的部分，而主要针对 `TO GO MO` 或 `OPEN TO GO MO`；已形成 `lot`、已 fixed 的顺序前端已尽量处理，不是所有订单统一先合并。

26. 颜色和材料项顺序，是必须严格执行，还是只要尽量优化即可？
    答：逐字稿更像“相同 model 下的 1 级、2 级排序/合并规则”，用于优化排序，不像 `FIX` 那样是绝对锁定规则。

27. 机型变化、Program 变化、颜色变化、材料项变化里，哪些变化一定算换线？
    答：当前逐字稿里明确进入 `change time` 匹配逻辑的是 `model` 和 `program`；匹配顺序是先 `model_one -> model_two`，再反向 `model`，再 `program_one -> program_two`，再反向 `program`，最后走通配默认。颜色和材料项在当前逐字稿里没有被说明为 `change time` 的直接匹配维度。
