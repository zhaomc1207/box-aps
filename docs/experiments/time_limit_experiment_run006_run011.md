## 3. 结果分析

1. **随着 time-limit 增大，gurobi 目标与 gap 确有改进**  
   `best_obj` 从 `542.65` 改进到 `416.75`，`gap` 从 `83.7004%` 降至 `76.1728%`。  
   但下降速度逐步放缓，边际收益递减。

2. **搜索形态未改变**  
   所有实验 `explored_nodes=1`，都停留在根节点强化与启发式改进，未进入有效分支树。  
   这限制了 gap 的进一步下降效率。

3. **业务指标呈“部分改善 + 波动”**  
   - `scheduled_demands` 整体上升（17027 -> 17061）
   - `unscheduled_demands` 整体下降（3384 -> 3350）
   - `effective_changeover` 明显下降（233 -> 155）
   - `fai_violation_count` 在 88~97 间波动，不随时长单调改善

4. **2h 与 3h 几乎完全等效**  
   `run_009_2h` 与 `run_010_3h` 的解结构和业务核心指标基本一致，仅 `best_bound/gap` 有轻微差异。

5. **4h 有进一步改进，但代价较高**  
   `run_011_4h` 在 `best_obj/gap` 和覆盖率上最好，但 FAI 违例回升（97），且计算时间翻倍。

## 4. 结论

- 仅靠提高 `time-limit` 可以持续改进，但已进入**边际收益递减区间**。
- 当前主要瓶颈不是时长，而是“根节点主导、未深入分支树”的搜索形态。

## 5. 建议的下一步

1. 把 `run_009_2h` 作为性价比基线（与 3h 几乎等效）。
2. 启动“模型开关 A/B”实验（固定 `time-limit`，如 1800s 或 7200s）：
   - `--no-activation-binaries`
   - `--no-enforce-fai-with-big-m`
3. 固定评估顺序，避免单指标误判：
   - `gurobi.log` 最终 gap
   - `unscheduled_demands`
   - `fai_violation_count`
   - `effective_changeover`
